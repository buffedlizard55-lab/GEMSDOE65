IR-65-001 · Propensity scale is not identifiable from PU data, and no reachable public index of exhaustively mapped quadrangles exists high

Finding. arXiv:1809.03207 Section 2/5.1 shows the propensity scale cannot be recovered from PU data alone: the likelihood is invariant to a scale transform, so the mean propensity over labelled positives a_bar = E[e(x)|s=1] must be fixed externally. The brief says to anchor it with exhaustively mapped quadrangles if a public index exists. No such index was reachable from this sandbox (nbmg.unr.edu, gbcge.org, usgs.gov, gdr.openei.org and buffedlizard55-lab.github.io are all off the egress allowlist), and the reachable peer-reviewed literature gives only an area share, not a pixel-level index.

Evidence. Measured a_bar sensitivity of pooled SAR DTI: 0.15 -> 0.06419, 0.25 -> 0.06183, 0.32 -> 0.06116, 0.50 -> 0.05574 (evidence/holdout_pu.json). The ranking is monotone in a_bar but NO anchor makes the SAR arm beat the nnPU baseline, so the gate conclusion is robust to this unidentified nuisance parameter. Also measured: lidar covers 0.7537 of the footprint while Faulds 2026 states detailed maps cover <25% of the region, so lidar coverage is NOT a valid mapping-completeness proxy and was not used as one.

Disposition. Reported as a sensitivity analysis over a_bar in {0.15, 0.25, 0.32, 0.50}; a_bar=0.25 pre-registered from the peer-reviewed ~25% detailed-mapping figure (Giddens & Faulds 2025, SGP-TR-229). No propensity value is ever quoted as an absolute probability on any deliverable page.

The withheld truth was outside the dilated visible set in most cells, so pooled DTI collapsed to ~0.0008 with no exception raised - a silent, non-crashing instrument failure that would have made every arm look useless and could have killed the lane on a false negative.

Disposition. Fixed once in the shared module used by every stage (no private fork). After the fix the instrument returns plausible non-degenerate DTI for all arms.

IR-65-003 · Duplicate-check Spearman used positional tie-breaking, so every pair of submission rasters looked correlated (rho ~ 0.97) critical

Finding. src/gems65/dupcheck.py spearman_subsample ranked values with np.argsort(np.argsort(x)), which breaks ties by ARRAY POSITION. Submission rasters are ~99.3% zeros, so the zero blocks of any two rasters receive nearly identical rank vectors and the reported rank correlation approaches 1 for statistically independent fields. The parallel-run protocol's drift trigger is rho > 0.90, so this bug alone would have declared lane drift on the FIRST build and stopped the lane on a false positive.

Evidence. Empirical demonstration on two independent binary fields with the same sparsity: buggy ranking rho = 0.9717, fixed ranking rho = 0.0000, scipy.stats.spearmanr rho = 0.0000. First full build reported max_rho = 0.9743 across all 15 registry rasters; after the fix the same corpus reports max surface rho 0.0318 and max 3-px dot overlap 0.0092. Regression test tests/test_dupcheck.py (5 tests) asserts independent fields give rho ~ 0 and that the implementation matches scipy.

Disposition. Fixed with scipy.stats.rankdata(method='average') in dupcheck.spearman_subsample and in the two local spearman() helpers in scripts/04_live_mirror.py and scripts/05_holdout_calibration.py that copied the same pattern. This is exactly the 'fix shared tool bugs once in the template, never keep a private fork' case.

IR-65-004 · EM initialisation deviated from the paper and produced a degenerate fixed point high

Finding. pu.fit_sar_em initialised the latent-positive model f with an nnPU risk at pi=0.5. The paper (Bekker & Davis 2018, Section 5.2) specifies initialising with a balanced model that treats the unlabeled examples as negative. With the wrong init the EM loop converged to f ~ 0.5 everywhere: mean predicted latent-positive probability on unlabeled pixels was 0.4946 and the observed-data log-likelihood got monotonically WORSE each iteration (-0.483 -> -0.612 over 8), i.e. the optimiser was moving away from the maximum.

Evidence. Fixed initialisation is a class-balanced weighted logistic fit on the selection indicator s via fit_soft_target_logistic, which removes the f==0.5-everywhere fixed point of the old init. The degenerate behaviour nevertheless PERSISTS in the re-run: over 8 iterations mean f|s=0 stays at ~0.45 against a Horvitz-Thompson prevalence pi=0.0517 and em_converged=false (evidence/submission_build.json). Bounded blast radius: the SAR arm's Definition-2 weights come from the ANCHORED propensity e, which is well behaved (range [0.0111,0.4521], coefficients relief +0.63 / slope +0.24 / basin_fill +0.27 / dist_range_front -0.196, i.e. higher selection probability on steep high-relief basin-margin terrain, matching the documented bias direction; 2.2% of weights clipped at 10), so the gate comparison does not depend on f's convergence. The 'em' arm does depend on f and is labelled reference-only for that reason.

Disposition. Init fixed in src/gems65/pu.py; the related NaN log-likelihood bug (np.clip(f,1e-12,1.0) -> log1p(-1)=-inf -> 0*-inf=NaN, so convergence could never trigger) is also fixed. IR stays OPEN: the EM has not been made to converge, so no EM-derived belief number in this repo is presented as a maximum-likelihood estimate.

IR-65-006 · The catalogue-hidden holdout structurally cannot reward the lane's own thesis high

Finding. The lane's mechanism is that the catalogue under-represents faults in LOW-propensity terrain, so a SAR model should reallocate belief there. The blocked-holdout proxy's 'truth' is the withheld part of the SAME catalogue, and that withheld truth concentrates in HIGH-propensity terrain. A model that correctly reallocates toward low-propensity terrain is therefore penalised by this instrument by construction. This is a measurement-validity problem, not a bug, and it means the gate result is evidence about the proxy, not conclusive evidence about the live metric.

Evidence. Measured: pooled DTI SAR 0.06183 vs nnPU 0.06687, delta -0.00504, 95% CI [-0.01015, -0.00111], 2/8 cell wins. The deficit is concentrated exactly where the mechanism predicts: the top-propensity tercile shows SAR 0.06383 vs nnPU 0.07490 (delta -0.01107), i.e. SAR gives up more in high-e terrain than it gains in low-e terrain against catalogue-derived truth. Independently, the template's own prior audit found the catalogue-hidden holdout DRIFTS from live truth (+0.0100 holdout vs -0.0033 live-anchored for the same ranking change), so holdout numbers are proxies only. ADDITIONAL, STRONGER EVIDENCE (stage 05, n=10 registry rasters with owner-reported live scores): Spearman(blocked-holdout pooled DTI, live score) = -0.436 and Spearman(dot count, live) = -0.791. The instrument is ANTI-correlated with the only live evidence available, and the mechanism is now identified: live scoring masks known-fault pixels (forum thread 11516) while this holdout's truth IS catalogue pixels, so catalog-adjacent artifacts (e.g. live 0.2376 -> holdout 0.00000; live 0.2778 -> holdout 0.00452) score near zero on the holdout and the off-catalogue artifacts (holdout 0.0967-0.0997) carry no live score at all. Consequence: the pre-registered gate is respected (not passed -> negative result, no promotion) but it is NOT evidence that the SAR mechanism fails live.

Disposition. Gate respected as pre-registered: not passed, so the lane is logged NEGATIVE and no file is cleared for submission. Reported together with the measured anti-correlation of the instrument, so the negative result is not over-claimed: it is a negative result ABOUT THE PROXY. The registry-anchored mirror (scripts/04_live_mirror.py) is published as the second, differently-biased view.

IR-65-008 · EM convergence diagnostic was mislabelled: the logged 'll' was only the f-part of the complete-data likelihood medium

Finding. src/gems65/pu.py fit_sar_em logged sum_i w_i [yhat_i log f_i + (1-yhat_i) log(1-f_i)] as the EM log-likelihood and used its change as the convergence criterion. That quantity is only the f-part of the expected complete-data log-likelihood; monotonicity of a PARTIAL quantity is not an EM guarantee. So the observed monotone decrease (-0.6521 -> -0.6659 over 8 iterations, decrements shrinking to ~0.0012) neither proves nor disproves convergence, and the convergence test built on it was uninformative in both directions.

Evidence. The SAR observed-data likelihood is sum_i w_i [ s_i log(f_i e_i) + (1-s_i) log(1 - f_i e_i) ]; this is the quantity EM must not decrease. Both are now recorded per iteration as ll_observed and ll_f_surrogate (em_history in evidence/submission_build.json from the next run onward).

Disposition. Fixed in the shared module src/gems65/pu.py (no fork). The already-published artifacts predate the fix, so their em_history 'll' column must be read as ll_f_surrogate. IR-65-004 stays open until ll_observed is shown non-decreasing on a real run.
