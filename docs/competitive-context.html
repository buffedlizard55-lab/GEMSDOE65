What can be established about the cited score?

A public leaderboard observation is not enough to identify the TIFF that produced it. The available project records do not include a receipt connecting the named H33 artifact to a submission score.

Correction to the premise

The GEMSDOE32 page for its named H33 artifact labels it “UNSCORED.” Its submission manifest has no receipt for that file, and the related PR #9 describes a projected / owner-reported development value rather than an organizer-confirmed score. None of these records ties the H33 TIFF to an official submission receipt.

What the public board can and cannot prove

The official DrivenData leaderboard is participant-level context, not a file-level provenance record. It does not, by itself, identify an uploaded filename, raster hash, model, or the run behind a row. Accordingly, this repository no longer stores or displays leaderboard rows and does not run a recurring fetch.

The DrivenData Terms of Use prohibit automated access for monitoring/copying and manual monitoring/copying without prior written consent. No written permission or officially authorized API has been established here. The project therefore links to the organizer's live page without mirroring its content. Do not treat a user-reported value or an unlinked public row as receipt-backed evidence.

Why the score cannot be explained from the H33 download

The available H33 records mark the named artifact as unscored and provide no submission receipt. A public leaderboard row that lacks file attribution cannot establish that this TIFF generated the row. Therefore the answer to “why did this file get that score?” is unknown; the file-to-score premise is not verified. Explaining an unverified result from its raster would be speculation.

The official metric definition says distance-weighted Tversky rewards predictions near expert-labelled faults using a triangular distance kernel and weights false negatives more heavily than false positives. That describes the metric, not the training method or performance of this artifact. It cannot explain an unverified score.

Can GEMSDOE65 exceed the cited value?

Possible in principle; not established here. This checkout has no experiment data, required shared hide-and-recover evaluator, submission writer, or prior-raster registry; it has no HOLDOUT-DTI or CI and no new TIFF. The only defensible project verdict is negative until the SAR candidate beats both the current holdout best and matched nnPU baseline overall, passes the highest-propensity-tercile gate, and the exact raster passes uniqueness and format checks. If the current holdout best cannot be established, promotion is blocked.

The project lane's scientific question is whether an explicit catalogue-inclusion propensity model improves blocked recovery of withheld fault segments, not whether it can imitate a prior dot pattern. This can address a plausible limitation in the training labels; only independent validation can show whether the correction helps.
