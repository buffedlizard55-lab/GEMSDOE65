How to submit a validated fault-prediction GeoTIFF

This page describes the upload steps and format checks. It does not submit anything on your behalf and does not imply that a candidate is ready.

Current status: do not submit

There is currently no downloadable or approved GEMSDOE65 TIFF. No model was trained, no segment-blocked holdout was run, no uniqueness check was possible, and no validator was run. The submission gate is negative. Do not use an artifact from another GEMSDOE project as a substitute.

Before opening the competition form

  1. Return to the status page. Proceed only if it presents an explicit green Promote / cleared to submit state and a unique download button for the candidate from that run card. A research note, projected score, old file, or format-only check is not promotion.
  2. Check the run card. It must contain the holdout evaluator version, withheld-positive count, paired HOLDOUT-DTI and 95% CI, registry correlation and dot overlap, raster SHA-256, and passing validator results. The candidate must beat both the current holdout best and matched nnPU baseline overall, and not lose in the highest-propensity tercile; if the current best is unavailable, do not promote. Do not spend a weekly slot before those scientific and uniqueness gates pass; follow the current competition rules for caps and final selection.
  3. Download the exact TIF shown next to the approved status. Do not rename a prior file to make it appear unique. Keep its SHA-256 and the exact short comment beside it.

Format checklist

The official problem description requires a single-band float32 GeoTIFF in UTM zone 11N (EPSG:32611), at the training-grid resolution (100 m), with exactly the training bounds/geotransform. Values inside the footprint must be finite and between 0 and 1; outside-footprint cells must be null/NaN. The local validator must also check that no out-of-range nodata sentinel is being written inside the footprint.

These are format conditions only. Passing them does not show the candidate detects new faults or will score well.

Upload steps in DrivenData

  1. Open the DOE GEMS competition page and sign in to the competition account. Review the official problem description and rules entry point.
  2. Open the competition's submissions page: DrivenData submissions. Choose New submission.
  3. Under File to submit, choose the approved single-band GeoTIFF downloaded from this project's status page. The submission form may accept a single GeoTIFF or a ZIP containing one GeoTIFF; prefer the direct .tif when it is offered and do not upload extra files.
  4. In Note (optional), paste the short, unique note shown for that exact candidate. Keep the note under 140 characters for this project, even if the form permits more.
  5. Before selecting submit, confirm the filename, note, checksum, and green gate all describe the same run. If the form reports that predictions are outside [0, 1], stop and report the error; do not clip a different file and re-upload without rerunning validation.
  6. Submit only after the checks above. Save the organizer's submission-page receipt and resulting score record. Those receipt details are the only evidence used here to attribute an organizer score to a particular raster.

How score evidence is reported

  • HOLDOUT-DTI: report evaluator version, number of withheld positives, and a 95% CI; state clearly that it is a blocked catalogue hide-and-recover proxy, not an organizer score on unknown faults.
  • ORGANIZER-CONFIRMED: copy from the submission-page receipt and tie it to the file hash. A live leaderboard entry without a receipt is not enough to identify the TIFF that produced it.
  • Negative: if a gate is unrun or failed, record the reason and keep the download disabled. No score is inferred from a projection.
The challenge has a two-round evaluation structure described on the official problem page. Check the current rules and submission interface for deadlines, slot limits, and final-selection requirements; this site does not assume that a format-valid upload is the correct competition entry.
