Executive summary · how to submit

How to submit, in order, in about two minutes

Read the status page first.

The download decision (cleared / not cleared) is stated at the very top of the status page and is reproduced verbatim in docs/data/run-card.json under verdict.one_line. Do not upload any file from this project unless that line reads DOWNLOAD AND SUBMIT.

The five steps

  1. Download the one file. From the status page, use the single-click link to the …-zeros.tif candidate (a float32, EPSG:32611, 100 m, single-band GeoTIFF whose in-footprint values are all within [0, 1]). The repository's writer also produces a one-TIFF .zip with a byte-verified round trip — either form is a valid upload, and both encode the same prediction array. The …-nan.tif variant is a diagnostics encoding of the identical array (NaN outside the footprint); it exists so the footprint convention can be inspected, and it is not the recommended upload because an over-strict portal check can read NaN as out-of-range.
  2. Open the official submission form. Go to the DOE GEMS Prize competition page, sign in with the account that accepted the competition rules, and open the Submit tab of the competition. Nothing on this site is an upload endpoint; the organizer's form is the only one.
  3. Upload and name it. Select the downloaded .tif (or the matching .zip). Where the form asks for a submission name, paste the exact unique name from the run card (verdict_name / files[…].file stem) so the artifact is identifiable later; where it asks for a note, paste the ≤ 140-character note recorded in the run card. Do not rename the file to reuse an earlier submission's name — the whole point is that this raster is new and unique.
  4. Submit, then read the receipt honestly. The portal returns an immediate score and a submission id. Copy that value into the run card only as ORGANIZER-CONFIRMED, tied to that id. A score shown anywhere else — a projection, a fold measurement, a user report — stays labelled as what it is.
  5. Mind the submission cap and the deadline. The competition permits a single submission for the prize evaluation; the same submission is rescored in the final round against an expert-expanded label set. Spend the slot deliberately, on the artifact whose evidence gate passed.

What "cleared" means here — and what it does not

Cleared means

Local gates passed

The candidate's numbers were produced by the shared evaluator with the whole-segment blocked hold-out and the documented dot budget; the SAR/propensity candidate met the promotion gate against its matched baseline and the highest-propensity tercile; the on-disk file re-passed the range/format validator; and the registry uniqueness test found no duplicate among the staged, hash-verified prior rasters.

Cleared does not mean

Predicted leaderboard performance

No organizer score exists for this file until it is submitted. A HOLDOUT-DTI measurement is an internal instrument value with its own evaluator version and confidence interval, and it is not a leaderboard forecast. This project never writes a projection as a score, and no score is claimed here.

If the file is not cleared

The run card records verdict.download_cleared = false with the failing field named (gate, validator, or uniqueness), together with the whole experiment as a negative result. In that state: do not download, do not upload, and do not spend the single submission slot on a placeholder. The site's status page will say exactly which gate failed and what evidence exists — that is the honest deliverable.

Reproduce every number before you trust it

python3 scripts/restore_inputs.py --check          # verify the pinned input hashes
python3 scripts/build_registry_index.py --check    # re-fingerprint the prior-raster registry
python3 -m unittest discover -s tests -v           # policy + run-card + audit tests
python3 scripts/audit_lane_readiness.py            # fail-closed presence audit
python3 scripts/run_lane.py canary                 # leakage canary on the blocked folds
python3 scripts/run_lane.py holdout --folds 0      # matched arms + declared wire rule
python3 scripts/run_lane.py emit                   # gate-gated emission, then validate

Every command above writes a JSON artifact under evidence/; the run card is the single place where the verdict is asserted. Never edit a run card by hand.
